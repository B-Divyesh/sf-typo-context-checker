How it works

Check new code tokens as you edit

  1. 01

    Open a local workspace

    Context Check builds a local vocabulary from permitted files, excluding environment and secret paths by default.

  2. 02

    Review a close match

    A VS Code inline diagnostic names both tokens and describes the differing character or length.

  3. 03

    Decide and move on

    Use the existing token with Quick Fix (and VS Code Undo), dismiss that exact pair, or disable a sensitive path. The choice stays local.

Install the local extension

Download the VSIX, open VS Code Extensions, choose Install from VSIX…, then open a repository. Use Context Check: Refresh repository vocabulary after large changes. The Chromium companion checks visible GitHub pull request, commit, and compare pages.

Privacy

Your source stays on your device.

Matching happens entirely on your device. Context Check has no analytics SDK, account, server, model API, or telemetry endpoint. VS Code and browser settings and dismissals use local extension storage.

Product questions

Questions about Context Check

Is this a spell checker?

No. It ignores prose. It looks for a new code-like token that is unusually close to a token already present in the surrounding repository context.

Does it diagnose dyslexia?

No. It is an accessibility-minded review tool for anyone who benefits from an explicit token comparison. It never evaluates a person.

Will it block a merge?

No. It shows an informational VS Code diagnostic only. It does not change CI status or make a change without your Quick Fix choice.

Can I exclude sensitive files?

Yes. The VS Code extension starts with patterns for environment files, secret directories, and PEM files. Add one workspace-relative path or wildcard in Settings.
